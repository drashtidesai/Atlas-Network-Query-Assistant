Fictional Atlas Retail network. All addresses and configurations are training data.

1. Addressing and physical links
devices.csv, links.csv, addressing.csv and services.csv enumerate every modeled device, connection, routed address, VIP, and server. DXB users: 10.10.10.0/24 VLAN 110; management: 10.10.99.0/24 VLAN 199. LON users: 10.20.20.0/24 VLAN 120; management: 10.20.99.0/24 VLAN 299. Gateways are .1 (VRRP), routers .2/.3, switches management .21/.22. DXB router IDs: 10.255.10.1/.2; LON: 10.255.20.1/.2 (all /32).
WAN-A 10.0.0.0/30: DXB-R01 .1, LON-R01 .2. WAN-B 10.0.0.4/30: DXB-R02 .5, LON-R02 .6. Site iBGP transit: DXB 10.10.254.0/30, LON 10.20.254.0/30, R01 .1 and R02 .2. Transit networks are not exported through BGP.
Router Gi0/0/0 is WAN, Gi0/0/1 is the LAN trunk, Gi0/0/2 the direct iBGP link, Gi0/0/3 unused. Each switch Gi1/0/1 faces its router, Gi1/0/2 and /3 form Port-channel1, /4-/8 are user access, /9-/12 on SW01 serve LOG/NMS/AAA/NTP respectively. Corresponding server ports on SW02 are reserved and shut. /13-/24 and Te1/1/1-/4 are shut. Endpoint devices use static addresses in the demo.

2. BFD and BGP
Every router has interface command bfd interval 300 min_rx 300 multiplier 3 on WAN and interrouter interfaces, no bfd echo, and neighbor fall-over bfd on its eBGP and iBGP peers. Asynchronous control packets are used; routed paths must pass BFD single-hop UDP 3784 and TCP 179. With matching negotiated 300-ms intervals and multiplier 3, expected BFD detection is about 900 ms, not a guaranteed total traffic recovery time. This moderate lab starting value trades detection speed against scheduling/jitter sensitivity. Validate CPU, packet loss, carrier treatment, and actual negotiated timers; relax to e.g. 1000 ms x 3 on a lab image that cannot sustain 300 ms. BGP keepalive/hold 10/30 seconds remains a fallback where BFD is unavailable; no strict-mode or graceful-restart helper behavior is explicitly configured. Verify inherited defaults before measuring.
Inbound eBGP route-map WAN-IN applies local preference 200 on R01, 150 on R02. LOCAL-SITE allows exactly the local user /24, management /24, and two local loopbacks /32. REMOTE-SITE allows the equivalent four remote prefixes. iBGP uses next-hop-self and permits the eight documented site prefixes. Both directions have explicit filters. Maximum-prefix 4 on each eBGP neighbor is appropriate only for this fixed corpus and must be revised if prefixes are added.

3. VRRP
IPv4 VRRPv2 syntax is used. User groups: DXB 110, LON 120. Management groups: DXB 199, LON 99 (group numbers are independent of VLAN numbers and must fit 1..255). VIP .1 is not a physical router IP. R01 priority 120, R02 100; both decrement by 40 when their own WAN physical line protocol fails. R01 uses preempt delay minimum 30 to avoid immediate failback; R02 preempts without that delay. Advertisement interval is 1 second. Backup master-down estimate at priority 100: 3 + (256-100)/256 = 3.609 seconds. Startup, priority-change, platform scheduling, ARP and forwarding updates affect observed recovery.
Tracking is physical WAN line protocol ONLY. A silent carrier or BGP-only failure does not automatically lower VRRP priority. In that case BFD/BGP and the direct interrouter path provide routing recovery. BFD is not directly attached to VRRP in this design. If the interrouter path and one WAN fail together, gateway reachability can fail despite local link-up tracking; this is a documented compound-failure limitation.

4. Layer 2
Rapid-PVST is configured with SW01 priority 24576, SW02 28672. Both interswitch links belong to the same ordinary LACP bundle. Native VLAN 999 is unused and excluded from the trunk allowed list; all service VLAN traffic is tagged. Router-facing switch ports have no PortFast; user/server access ports have PortFast and BPDU Guard. There is no BFD on this Layer 2 port channel: LACP/physical state detects its member failure. Management VLAN 299 is valid even though VRRP group 299 would not be.

5. Platform and credentials
Router target C8300-1N1S-4T2X, autonomous IOS XE; switch target C9200L-24T-4X, independent units with member number 1. Interfaces and features require exact image/license confirmation. All modeled data ports are copper RJ45; there are no CE SFPs. Provider transport optics, serial numbers and bill of materials are unknown. Every <REDACTED> value hides a credential field. Bootstrap RSA keys separately with crypto key generate rsa modulus 2048 after hostname/domain provisioning; persistent key material is not represented by a text config. Boot variables, licenses, certificates, default/hidden commands and platform management-port defaults are outside the generated baseline. No actual configurations have been pushed to hardware.
