FIFTEEN WORKFLOW DEVELOPMENT EVALUATION

Scope freeze: four router targets, five existing check domains, current three-role
workflow, existing 27-file evidence corpus. No new agents or platforms for this
evaluation. Cases are a visible development set, not held-out generalization proof.

Prepare (user runs): uv run python prepare_workflows15.py --prepare
Creates inputs/evaluation15/W01.txt through W15.txt, a case manifest and an
unscored results template. These are authored fictional proposals, not device
changes. Existing result scores are not overwritten. No API calls are made.

Use Upload a proposal for every case, selecting the router, fault injection and
request exactly as recorded in workflow15-cases.json. Enable three-agent mode.
Never ingest evaluation labels into the corpus or agent prompts. W11 is an
expected input rejection, not a model failure; do not pay for that case.

Score separately:
- Finding accuracy: correct / partial / incorrect / not applicable.
- Workflow outcome: completed / expected_block / failed / not_run.
- Evidence quality: supported / partial / unsupported / not applicable.
- Human correction: distinguish answering missing intent from repairing mistakes.
- Efficiency: model decisions, reported tokens, active seconds, full elapsed time.
Unknown or unexecuted metrics stay null, never guessed. Correct expected rejection
or unresolved closure may pass that specific workflow but not answer accuracy.
No 15-case aggregate success rate until all cases have an explicit adjudication.
Use original drafts for first-pass accuracy; do not replace their scores with
human-corrected final outputs. Preserve traces and describe code versions/iterations.

Human interactions:

not deployment. W04: intention is review/planning only; implementation unauthorized.

W13: cancel persistent-failure handoff and confirm no approved artifact.

Other cases: inspect report before any approval. Failures must not be marked passes
merely because the app safely stopped.
